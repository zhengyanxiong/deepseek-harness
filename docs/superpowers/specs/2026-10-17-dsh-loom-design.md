# DSH Loom（织码）首版设计评审稿

日期：2026-10-17。状态：待用户确认，未开始功能实现。本文记录拟实现的产品规则，不是已实现能力说明。

## 摘要与范围

Loom 在 DSH 内提供完整多项目工作台，串联项目、版本、Lock、任务、工作区及原生会话。首版目标是：用户为一个版本下的任务准备可追溯的多仓库工作区，通过多个会话接续开发同一份代码，最后人工验收。

首版支持手动创建项目和配置导入，共用校验及预览流程；导入不自动拉取仓库或运行脚本。目录扫描留到后续。PR、CI、成本、吞吐统计及依赖图是扩展信息，不作为首个闭环的前置条件；没有真实数据时不显示模拟业务数据。

## 页面设计

Loom 是 DSH 主面板中的独立完整插件页面，不是散布在原生页面上的装饰。保留 DSH 外层窗口与导航栏，Loom 管理其内部布局。

```text
DSH 导航栏 → Loom 页面
├── 顶部：项目 / 版本 / 工作区状态 / 工作台与看板切换 / 新建
├── 左侧：项目、版本、任务、关联会话及临时会话入口
├── 中央：原生会话区，或任务看板
├── 右侧：当前上下文，或看板统计与阻塞信息
└── 底部：Diff / 终端 / 测试 / 审计 / 成本，默认收起
```

中央整体复用原生消息流、工具卡片、审批卡片、输入框、模型选择及权限控件，不自建聊天或审批系统。Loom 在会话头部展示项目、版本、任务、执行轮次、模块、Lock 和工作区分支等元信息。

底部默认只显示带计数或状态的标签栏，点击展开。Diff 使用 DSH 原生渲染器；终端优先复用原生终端。Loom 提供工作区变更数据，不重写 Diff。

看板卡片代表任务，一项任务可关联多个会话。保留指标条、项目泳道和平铺两种排布、WIP 提示、活跃会话和风险区。任务列采用待办、进行中、待验收、已完成、失败；等待审批和等待工作区属于执行状态，不是任务完成度。

布局沿用认可的视觉稿 v2，像素尺寸仅作参考；主题跟随 DSH token，产品文案使用国际化机制。早期视觉稿中的独立 Review/测试列及“不允许 AI 辅助流转”的描述，以本文规则替代。

## 整体功能与 UI 评审范围

本节补齐整体产品视图。已确认规则沿用后文；下面的界面细节作为本次评审建议，等待用户一起确认，不表示已实现。

### 功能地图

| 功能区 | 用户可以完成的操作 | 首版范围 |
|---|---|---|
| 项目管理 | 创建项目、导入配置、查看项目、编辑未执行的配置 | 必做；目录扫描后续提供 |
| 仓库与模块 | 配置仓库来源、相对目录、模块路径和归属 | 必做；不把模块当安全权限 |
| 版本管理 | 创建项目版本、配置参与仓库及目标分支或标签、查看版本任务 | 必做 |
| Lock 管理 | 解析仓库 commit、生成不可变快照、查看历史及各仓库基线 | 必做 |
| 任务管理 | 创建任务、设置模块与优先级、关联会话、验收、确认失败、重启 | 必做 |
| 工作区管理 | 准备全仓库 worktree、复用现场、查看占用、等待或接管、显式清理 | 必做 |
| 会话工作台 | 创建和切换原生会话，显示任务上下文及交接摘要 | 必做；完整保留原生能力 |
| 看板 | 项目泳道或平铺、任务筛选、状态调整、查看阻塞 | 必做；完成和失败需人工确认 |
| 变更检查 | 汇总各仓库改动，按仓库和文件查看原生 Diff | 必做；不自动提交或合并 |
| 业务审计 | 查询 Lock 锁定、执行权交接、任务状态、准备与清理结果 | 首版最小可追溯记录 |
| 终端与测试 | 原生终端入口、展示真实测试执行结果 | 接口验证后接入；不另建执行器 |
| PR、CI、成本、吞吐与依赖图 | 查看外部协作及统计信息 | 后续集成，不用示意数据冒充真实能力 |

### 页面一：完整工作台

顶部提供项目和版本选择、当前工作区状态、工作台与看板切换、新建入口及 Loom 设置。项目切换不会停止后台任务，界面明确标出仍在执行的会话。

左侧按项目 → 版本 → 任务 → 会话组织导航，并提供置顶项目和临时会话入口。任务与临时会话分开命名，避免将未绑定任务的会话误认为看板任务。

中央复用完整原生会话，任务元信息放在会话头部。无选中会话时展示项目或任务摘要与开始入口；准备工作区时展示逐仓库进度；准备失败时展示失败项与重试入口，不进入看似可用的会话状态。

右侧展示当前任务、模块、轮次 Lock、仓库分支、未提交改动、工作区占用和相关会话。接管时可查看前序摘要及尚未完成事项，不能把摘要当作代码状态的替代依据。

底部默认折叠为标签栏，点击标签展开，允许再次收起。Diff 按仓库和文件组织，复用原生渲染。测试、审计和成本区域只显示真实来源数据；尚未接入的区域明确说明，不显示伪造指标。

### 页面二：任务看板

顶部指标显示任务数量、进行中任务、活跃会话、待审批和阻塞信息。支持项目、版本、模块、优先级、状态及关键词筛选；跨项目查看时可选择全部项目。

默认按项目泳道分组，也可平铺。列为待办、进行中、待验收、已完成、失败。WIP 超限先提示，不隐式终止任务。

卡片展示标题、项目版本、涉及模块、优先级、会话数、当前轮次、活跃执行与阻塞标记。点击打开任务详情；拖拽调用与详情页相同的状态校验，不能绕过完成、失败确认或执行轮次规则。

右侧展示真实的活跃会话、待审批、工作区等待及最近活动。吞吐图、PR 和 CI 信息仅在对应数据源接入后显示。

### 配置和操作界面

| 界面 | 核心内容与操作 |
|---|---|
| 新建项目 | 项目名称 → 仓库来源和目录 → 模块 → 配置预览与确认 |
| 导入项目 | 选择配置 → 校验结果 → 仓库、路径及模块预览 → 确认保存；不执行导入内容中的任意脚本 |
| 版本详情 | 版本配置、参与仓库、模块、Lock 历史和版本内任务 |
| Lock 详情 | 每个仓库的引用与精确 commit、生成结果；不可编辑既有快照 |
| 任务详情 | 描述、所属版本、模块、优先级、状态、轮次历史、Lock、工作区、会话及结果摘要 |
| 首次执行 | 确认 Lock、创建或显式选择兼容工作区、逐仓库准备、成功后启动原生会话 |
| 继续会话 | 在当前轮次原工作区创建会话；工作区被占用时提供等待或接管 |
| 失败重启 | 选择同版本 Lock，确认保留原现场或创建新现场，建立新轮次且保留旧记录 |
| 验收与失败确认 | 展示 Agent 摘要、代码变更和可用测试结果，由用户确认状态 |
| 工作区详情与清理 | 展示路径、仓库状态、关联会话、执行权和清理风险；运行中禁止删除 |

### 通用交互要求

窄屏优先保留原生会话，侧栏和上下文面板可收起；具体断点跟随现有 DSH 布局规范。长项目名、分支名及路径允许查看完整值，不挤掉关键操作。

每个异步操作提供加载、成功、失败及可恢复状态。失败提示包含影响范围和下一步，不能以静默跳过伪装成功。高风险确认展示目标项目、任务、工作区及影响，避免仅用“确定吗”。

使用 DSH 原生视觉 token、交互组件和国际化机制。键盘操作、焦点恢复和菜单行为遵循 DSH 现有规范，不额外构建一套不兼容的 UI 系统。

### 首版明确不包含

首版不做目录自动扫描、不复制原生对话或审批、不自动提交/推送/合并代码、不实现跨仓库原子提交、不让多个会话同时写同一工作区、不在未经用户确认时删除代码现场。完整界面骨架不代表所有扩展集成都在首个里程碑完成。

## 业务对象

| 对象 | 职责与约束 |
|---|---|
| Project 项目 | 组织仓库、模块与项目版本 |
| Source 仓库 | 代码来源及工作区内相对路径 |
| Module 模块 | 业务范围，指向一个仓库内目录 |
| Version 项目版本 | 本版本包含的仓库、模块及分支或标签配置 |
| Lock 快照 | 各仓库精确 commit，生成后不可修改 |
| Task 任务 | 归属一个项目的一个版本，可涉及多个模块 |
| Attempt 执行轮次 | 本轮 Lock、执行记录及工作区关联 |
| Workspace 工作区 | 多仓库 worktree 与当前代码现场 |
| Session 会话 | 原生 DSH 会话，Loom 仅记录关联关系 |

一个仓库可有多个模块，首版每个模块只归属一个仓库；跨仓库任务选择多个模块。模块用于聚焦任务与上下文，不是文件权限限制，权限仍由 DSH 沙箱和审批控制。

一个版本可保留多份不可变 Lock。版本配置和新 Lock 不自动改变已有工作区。任务只属于一个项目版本，不能在同一仓库的不同版本线间切换。项目级待规划条目需确定版本后才能进入任务执行流程。

## 任务与执行轮次

```text
待办 → 进行中 → 待验收 → 已完成
          ↓        ↓
        失败     进行中（验收退回）
          ↓
       新一轮执行
```

任务待办阶段可调整候选 Lock；首次执行时确认并固定本轮 Lock，默认选同一版本最新的适用快照，也可选历史快照。暂停、审批等待、工作区等待、工具重试和更换会话不解除锁定。

Agent 可以提交结果并申请待验收，但会话结束不等于任务完成。完成由用户确认。Agent 可以建议任务失败并提供原因，但最终失败也由用户确认；单次工具或会话报错不自动判定任务失败。

用户可以手动调整状态。存在活跃执行时标记完成必须提示；状态变化不隐式停止会话或释放执行权。

失败后重启创建新执行轮次，可以沿用原 Lock，也可选择同一项目版本下的新 Lock。旧轮次、快照、会话关联和结果保留。沿用原 Lock 且用户选择保留现场时可复用工作区；换 Lock 时默认新建，旧现场不覆盖或自动删除。

已完成任务保留执行记录；首版不提供无记录地清零重跑，后续工作用关联新任务表达。

## 工作区与会话

**同一任务、同一执行轮次使用同一套工作区；新建会话不新建 worktree。**

```text
任务 → 当前执行轮次 → 一套多仓库工作区
                       ├── 会话 1：实现
                       ├── 会话 2：接续开发
                       └── 会话 3：验证
```

后续会话直接继续当前成果，包括已提交与未提交改动，不要求为换会话而提交、复制或搬运代码。Lock 记录初始基线，开发中新产生的提交属于成果，不是变更任务基线。

不同任务默认独立工作区。用户可显式选择已有工作区，但必须核对版本、基线及实际成果状态并确认，不得自动重置。复用产生真实共享修改，不能呈现为隔离副本。

不关联任务的临时会话默认独立工作区，也可显式复用。新会话通过任务信息和交接摘要接续上下文，不假设拥有旧会话的完整历史；代码现场通过工作区延续。

工作区按 Lock 准备当前项目版本包含的全部仓库，模块选择不裁剪仓库。

```text
工作区根目录/
├── frontend/    # 前端仓库 worktree
├── backend/     # 后端仓库 worktree
└── shared/      # 公共库 worktree
```

DSH 会话工作目录为统一根目录。各仓库保留各自分支、Git 状态与提交历史，根目录不额外初始化 Git 仓库。相对路径由项目配置指定，拒绝越界、重叠及冲突。变更统一展示、提交分别发生，不承诺跨仓库原子提交。

## 并发与接管

同一工作区一次只允许一个会话执行 Agent 任务；其他会话可以浏览，但不能同时启动修改现场的执行。

- 等待：展示占用会话，执行权释放后再调度。
- 接管：用户确认后请求停止原执行，确认工具及子任务都停止后才能交接。
- 停止失败或结果未知：保持阻塞，报告原因，不能直接抢占。
- 保留现场：接管不自动提交、丢弃修改、重置或切换分支。

执行权约束 Loom 管理的执行路径，不是操作系统级隔离；外部编辑器或终端仍可能修改代码。

## 保留与清理

会话结束默认保留工作区，删除会话不级联删除共享工作区。清理由用户显式发起；有未提交改动或关联会话时需展示影响并确认；仍有任务运行时禁止清理。

实现还需保护尚未安全保留的本地提交，不能把没有未提交修改等同于删除安全。清理仅处理 Loom 拥有的 worktree 和元数据，不删除用户复用的外部仓库本体。部分失败要分别报告成功项和未完成项。

## 技术约束

本节是实现要求，尚未验证具体接口可用性。

Loom 管理项目、任务、Lock、工作区关联与业务审计；DSH 管理会话、Agent、工具执行、审批、沙箱和消息日志。Loom 引用原生会话 ID，不复制消息或修改 Agent 循环。

编码前通过 Cordis Inspect 和源码核对独立页面挂载、原生会话嵌入、Diff 接口及停止执行能力。接口缺口需报告并确认最小扩展方案，不能用仿制聊天框替代完整原生复用。

Git 操作统一封装，准备过程记录步骤。多仓库准备失败时只撤销本次创建且可安全撤销的资源，保留既有资源和用户修改，分别报告主错误和回滚失败。

执行权覆盖重复请求、并发启动和进程重启后的状态核对；超时或服务重启不能作为旧执行已经停止的证据。

导入配置及 AI 输出均视为不可信输入，经过语法、结构、引用、路径校验及用户确认。凭据不进入项目配置、Lock 和审计明文。高风险操作走 DSH 审批，审批不可用时不得自动同意。

首版优先本地持久化。存储字段、具体工具名称和服务方法在能力探针后确定，本文不假定存在尚未核对的接口。

## 开发阶段与验收

### A：原生能力探针

验证 Loom 独立页面入口、原生会话完整复用、Diff 接入、会话工作目录绑定。最小页面及只读查询使用真实数据，不自动修改部署 profile。

验收：原生输入、模型选择、工具卡片与审批保留可用；发现接口限制时明确记录并报告。

### B：项目、版本与 Lock

实现手动创建和配置导入、仓库与模块关系、版本配置和不可变快照。

验收：版本能保留多份快照；非法路径、无效引用及 commit 解析失败被明确拒绝，不生成半成品工作区。

### C：任务、执行轮次与工作区

实现首次执行锁定、多仓库准备、同任务会话复用、等待与接管、失败重启、保留与清理。

验收：同任务增加会话不增加 worktree；未确认停止不能交接；新 Lock 不影响活跃轮次；准备失败不破坏既有现场。

### D：完整工作台与看板

接入真实任务状态、验收及失败确认、项目泳道、上下文和原生 Diff，并覆盖等待、空状态和恢复流程。

验收：创建项目、建立任务、准备工作区、多会话接续、查看变更、人工验收完整走通。

测试覆盖配置校验、Lock 不可变、状态流转、并发首次锁定、复用、Git 回滚、执行权、安全接管和清理保护。使用临时 Git 仓库验证 worktree；用户可见变化补充仓库要求的快照，并用专用开发实例验证，不切换部署工作区。

## 评审重点

1. 工作区属于任务执行轮次，不属于任务内每个会话。
2. 首次执行固定 Lock，失败重启才能重新确认同一版本下的基线。
3. 同任务会话接续当前现场，包括未提交改动。
4. 共用工作区等待或安全接管，不抢占未知状态的执行。
5. 完成和失败由用户确认；原生会话与 Diff 必须复用。
